# PRD — 스토리나침반 (Story Compass)

Product Requirements Document. **무엇을 / 왜** 만드는지 정의한다.  
구현 세부·채점 Must는 [SRS.md](./SRS.md), 기술 설계는 [TRD.md](./TRD.md)를 본다.

---

## 1. 제품 한 줄

Save the Cat **15비트** 시트를 축으로, 작가가 씬(메모 조각)을 칸반처럼 배치·집필하는 글쓰기 길잡이 웹앱.

- **프로젝트명:** 스토리 나침반 (Story Compass)
- **슬로건:** 쓰다 막힌 당신의 이야기가 완결까지 길을 잃지 않도록, 15단계로 방향을 알려주는 나만의 글쓰기 길잡이

---

## 2. 목표·비전

| 구분 | 내용 |
|---|---|
| 주요 목표 | 도입~결말까지 이야기의 흐름을 잃지 않고 체계적으로 집필 |
| 사용자 | 시나리오·소설·웹소설 등을 쓰는 개인 작가 |
| 성공 기준 | 15비트(1·2·3막) 위치를 보며 씬을 배치·편집하고, 작업을 로컬에 안전하게 저장할 수 있다 |

---

## 3. 화면 레이아웃 (4영역)

시선 이동에 따라 고정된 4개 영역으로 나눈다.

| 영역 | 역할 |
|---|---|
| **Left** | 워크스페이스 탐색기 — 여러 프로젝트·문서 트리, 휴지통, 폴더 연결, 사이드바 접기 |
| **Top** | 프로젝트·문서 제목, 15비트 프로그레스(1·2·3막·마커·채움 통계), WorkspaceActions(저장 배지·테마·참고) |
| **Center** | 씬 캔버스 — X축=15비트 열, Y축=같은 비트 안 씬 순서(칸반), 검색·태그 필터 |
| **Right** | 참고 자료 드로워 — 비트와 무관한 메모, 검색·태그, 킵 모달 (열고 닫음) |

---

## 4. 핵심 사용자 경험

1. 문서를 고르고, 비트 열에 씬을 추가한다 (하단 버튼 또는 카드 사이 호버 삽입).
2. 씬 카드를 클릭하면 **킵 스타일 모달**로 제목·본문·태그를 편집한다. 제목만 비워 두고 본문만 써도 된다(카드는 「제목 없는 씬」). **제목·본문이 모두** 비면 닫을 때 생성을 취소한다.
3. 리치 HTML 본문(굵게·목록·이미지 등)을 작성한다.
4. 카드 전체 드래그 또는 ⋯ 메뉴로 씬을 비트·순서상으로 옮긴다.
5. Top 마커·비트 제목 클릭으로 해당 비트 열로 스크롤한다. 헤더 호버 시 짧은 안내 툴팁, 인포 아이콘으로 상세 모달.
6. 칸반·참고에서 제목·본문·태그 **검색**과 **다중 태그 필터**로 좁힌다 (영역별 독립).
7. 참고 드로워에서 설정 메모를 씬과 같은 카드·킵 모달·순서 변경으로 관리한다.
8. **새 워크스페이스** 또는 **기존 워크스페이스 열기**로 폴더를 연결하고, 한 폴더 안에 여러 프로젝트를 둔다. 변경은 디바운스 자동 저장된다.
9. 삭제한 씬·참고·문서·프로젝트는 앱 휴지통에 모이며, 복원하거나 영구 삭제(비우기)할 수 있다.
10. 씬·참고는 텍스트로 복사하고, 활성 문서는 비트 순 원고로 복사하거나 `.txt`로 저장한다. 결과는 하단 앱 토스트로 알린다.

---

## 5. 디자인 방향

- 집필에 방해되지 않는 정돈된 UI (Toss 톤 · Pretendard · Material Symbols)
- 라이트 / 다크 모드
- 제목을 투박한 폼 박스로 분리하지 않고, 노트처럼 이어지는 편집감
- 참고 메모만 연한 하늘색으로 씬과 구분
- 앱 피드백 토스트는 불투명 알약형(비트 툴팁과 같은 단색 톤·은은한 shadow)
- 최소 글자 11px, 데스크톱 우선

## 6. 범위 비전 vs 이번 제출

| 포함(비전·구현) | 이번 제출에서 후순위 / Won’t |
|---|---|
| 15비트·1·2·3막·칸반·참고 드로워 | Google Drive OAuth·실시간 동기화 |
| 워크스페이스·다중 프로젝트·휴지통·텍스트 추출·핸들 복원 | 협업·인증·자동 배포 |
| 검색·태그·DnD·퀵 이동·비트 안내 | 실사용자 개인정보 수집 |

Drive는 **동일 폴더 스키마**로 확장 가능한 후순위로 둔다.
